### 그림 전달 지연 (T25, 요구사항: 200ms 이하)

| 측정 방법 | 중간값 | 95% | 최대 | 빠진 조각 |
| --- | --- | --- | --- | --- |
| 서버만 (`tools/latency_check.py`, 8명) | 5ms | 7~12ms | 17~22ms | 0 |
| 브라우저 8개를 한 컴퓨터(CPU 2개)에서 동시에 | 176ms | 442ms | 491ms | 0 |
| **실서버** (Render 싱가포르, 한국 브라우저에서 8명, 8초) | 116ms | 122ms | 133ms | 0 / 1274 |

- 서버가 선을 받아 7명에게 나눠 주는 데는 10ms 정도면 충분합니다.
- 브라우저 8개 측정값이 큰 것은 작은 테스트 컴퓨터 한 대가 그림 그리기 화면 8개를 동시에 돌렸기 때문입니다. 실제로는 사람마다 자기 기기를 쓰므로 이 부담이 나뉩니다.
- 실서버 값은 출제자 브라우저 → 싱가포르 서버 → 다른 사람 브라우저까지 왕복을 잰 것입니다. 목표 200ms 안에 들어옵니다. (2026-10-21)
- 다시 재려면 아래 명령을 씁니다.

```bash
pip install "python-socketio[client]" websocket-client
python tools/latency_check.py https://draw-guess-6jsk.onrender.com 8 10
```

## 2. 지인 플레이 테스트 계획 (T24 — 사람이 필요)

### 준비

- 인원: 4~8명, 최소 2회 (1회는 같은 공간, 1회는 각자 집에서)
- 기기: PC와 휴대폰을 섞기 (아이폰 사파리 1명 이상 포함)
- 주소: https://draw-guess-6jsk.onrender.com (무료 서버라 처음 접속 때 50초쯤 걸릴 수 있으니, 진행자가 시작 1분 전에 먼저 열어 둡니다)
- 진행자는 3라운드를 끝까지 하고, 끝난 뒤 바로 아래 질문을 받습니다.

### 진행하면서 볼 것

- [ ] 초대 링크만으로 헤매지 않고 들어오는가
- [ ] 제시어 고르는 10초가 짧거나 길지 않은가
- [ ] 80초 동안 그리기 시간이 적당한가 (대부분 몇 초에 맞히는지 메모)
- [ ] 휴대폰에서 그리기·채팅이 불편하지 않은가 (키보드가 화면을 가리지 않는지)
- [ ] 그림이 끊기거나 늦게 보인 적이 있는가 (있다면 시각과 기기)
- [ ] 새로고침·잠깐 끊김 뒤 자연스럽게 돌아오는가
- [ ] 점수 차이가 납득되는가 (빨리 맞힌 사람이 더 높은지)
- [ ] 힌트(40초 초성)가 도움이 되는가
- [ ] 효과음이 거슬리지 않는가

### 끝나고 물어볼 질문

1. 다시 하고 싶나요? (1~5점)
2. 가장 재미있었던 순간과 답답했던 순간은?
3. 너무 어렵거나 그리기 곤란했던 제시어는? (`data/words.json`에서 빼거나 난이도 옮기기)
